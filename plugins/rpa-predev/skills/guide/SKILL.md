# RPA 개발 전 단계 가이드

| 단계 | 스킬 | 입력 | 산출물 |
|------|------|------|--------|
| 1. 과제 발굴 | `/rpa-predev:discovery` | 현업 조사서, 인터뷰 메모, 업무 목록 | `assessment.json`, `RPA_과제평가표.xlsx`(과제목록·스크리닝) |
| 2. 타당성 평가 | `/rpa-predev:feasibility` | assessment.json | 평가표 갱신 (점수·등급·ROI·우선순위) |
| 3. 프로세스 분석 | `/rpa-predev:process-analysis` | 1순위 과제의 업무 설명 PPT/자료 | `pdd.json`, `RPA분석서_<업무명>_v1.0.pptx` |
| 4. 솔루션 설계 | `/rpa-predev:solution-design` | pdd.json + 인터뷰 답변 | `sdd.json`, `RPA설계서_<업무명>_v1.0.pptx` |

## 시작하기

1. 사용자의 현재 위치를 파악한다: 이미 후보 업무가 정해졌는지, 분석할 업무 자료(PPT)가 있는지, PDD가 있는지.
   - 아무것도 없음 → 1단계 (조사 양식 생성부터)
   - 후보 목록은 있고 우선순위가 필요 → 2단계
   - 특정 업무 자료가 있음 → 3단계 (평가표가 없어도 바로 가능)
   - PDD 완료 → 4단계
2. 해당 스킬을 호출해 진행한다.

## 작업 폴더 권장 구조

```
<프로젝트>/
├─ 01_발굴평가/   조사서*.xlsx, assessment.json, RPA_과제평가표.xlsx
├─ 02_분석/<업무명>/   원본 자료, images/, pdd.json, RPA분석서_*.pptx
└─ 03_설계/<업무명>/   sdd.json, RPA설계서_*.pptx
```

JSON 파일은 산출물의 원본이다. 수정은 JSON을 고쳐 다시 렌더링하고, 버전을 올릴 때 `meta.version`을 바꾼다.

## 단계 간 품질 게이트

- **발굴 → 평가**: 후보마다 월 처리건수·건당 시간이 수치로 있어야 ROI가 계산된다. 없으면 현업에 먼저 확인.
- **평가 → 분석**: 1–2순위 과제부터 분석한다. "보류"는 프로세스 표준화가 선행 과제다.
- **분석 → 설계**: PDD의 "현업 인터뷰 필요 항목" 중 예외 처리 기준·계정/권한·시스템 제약이 해소돼야 설계가 확정된다.
- **설계 → 개발**: SDD 확인 필요 사항 확정, 봇 계정·권한·개발 환경 확보.

## 공통 원칙

- 자료에 없는 수치·사실은 추측하지 않고 "확인 필요"로 남긴다. 누락 정보를 드러내는 것이 이 산출물들의 핵심 가치다.
- 실제 비밀번호, 인증서, 개인정보 원문은 JSON과 산출물에 넣지 않는다.
