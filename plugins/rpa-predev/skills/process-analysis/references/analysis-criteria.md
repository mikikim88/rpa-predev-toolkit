# 7가지 분석 항목 상세 도출 기준

각 항목별로 어떤 정보를 어떻게 도출해야 하는지에 대한 가이드입니다. 자료에서 정보를 찾을 수 없으면 **"확인 필요(현업 인터뷰)"** 로 표기합니다.

---

## 1. 업무 개요/목적

### 도출해야 할 정보
- **업무명**: 한 줄로 명확히 (예: "월말 거래처 정산 데이터 ERP 등록")
- **업무 목적**: 왜 이 업무가 존재하는가
- **수행 부서/담당자**: 현재 누가 수행하는가
- **수행 빈도**: 일/주/월/분기/이벤트성 (RPA ROI 핵심 지표)
- **건당 처리 시간**: 1건 처리에 평균 얼마나 걸리는가
- **월간 처리 건수**: 월 평균 몇 건을 처리하는가

### 도출 팁
- PPT 첫 슬라이드 또는 표지에서 업무명 추출
- "왜 하는가"가 명시되지 않은 경우, 후속 작업이나 결과물 활용처에서 역추적
- 처리 시간/건수가 없으면 반드시 "확인 필요" 표기 (자동화 우선순위 결정에 필수)

### 체크리스트
- [ ] 업무명이 단일 명사구로 명확히 정의되었는가
- [ ] 처리 빈도와 건수가 수치로 명시되었는가
- [ ] 업무의 시작 트리거가 무엇인지 명시되었는가 (시간 기반? 이벤트 기반?)

---

## 2. 사용 프로그램/시스템

### 도출해야 할 정보
- **시스템명**: 정확한 명칭 (예: "SAP S/4HANA", "사내 그룹웨어 - 문서함")
- **접속 방식**: 웹 브라우저(URL), 클라이언트 프로그램, Citrix 가상화 환경 등
- **인증 방식**: ID/PW, SSO, OTP, 공인인증서, MFA
- **권한 수준**: 일반 사용자, 관리자, 특수 권한
- **사용 메뉴 경로**: 메인 → 하위메뉴 → 화면명 (예: 영업 → 거래처관리 → 정산조회)

### 도출 팁
- 슬라이드의 스크린샷에서 화면 상단 제목, 좌측 메뉴 트리, URL 바를 확인
- 현업이 "ERP에서"라고만 적었다면 정확한 ERP 종류와 버전을 "확인 필요"로 표기
- 가상화 환경(Citrix/VDI)은 RPA 구현 난이도가 크게 달라지므로 반드시 확인

### 자동화 관점 분류
| 분류 | 자동화 난이도 |
|------|---------------|
| 웹 (HTML 표준) | 낮음 |
| 데스크톱 앱 (UIAutomation 지원) | 중 |
| 가상화 환경 (Citrix/VDI) | 높음 (이미지 인식 필요) |
| 레거시 단말 (TN3270 등) | 높음 |

### 체크리스트
- [ ] 시스템명이 정확히 명시되었는가
- [ ] 인증 방식이 자동화 가능한 형태인가 (OTP/공인인증서는 별도 협의 필요)
- [ ] 메뉴 경로가 클릭 단위로 명시되었는가

## 3. 작업 단계(Step별 절차)

### 도출해야 할 정보
각 Step마다:
- **Step 번호**
- **수행 행위**: 동사 + 목적어 (예: "신청서 다운로드", "거래처 코드 입력")
- **대상 화면/필드**: 어느 시스템 어느 화면 어느 필드인가
- **입력값**: 무엇을 입력하는가 (직접 입력 / 이전 단계 결과 / 외부 파일)
- **확인 사항**: 다음 Step으로 넘어가기 전 무엇을 확인하는가

### 작성 형식 (표 형태)
| Step | 행위 | 시스템/화면 | 입력/조작 | 결과 확인 |
|------|------|-------------|-----------|-----------|
| 1 | 시스템 로그인 | SAP / 로그인 화면 | ID/PW 입력 | 메인화면 진입 |
| 2 | 거래처 조회 | SAP / FK03 | 거래처코드 입력 | 거래처 정보 표시 |

### 도출 팁
- **현업 자료의 절차를 그대로 옮기지 말 것**. 봇이 인식 가능한 수준으로 분해.
- 예: "거래처 정보 확인" (현업) → "거래처명, 사업자번호, 계좌번호 3개 필드값을 화면에서 읽어 입력 데이터와 비교" (분석서)
- 슬라이드 순서와 실제 작업 순서가 다를 수 있음 (현업이 설명 편의상 묶어놓은 경우 있음)
- 마우스 동작과 키보드 동작을 구분 (탭 이동, 단축키 등)

### 체크리스트
- [ ] 각 Step이 봇의 단일 행위로 분해되어 있는가
- [ ] 화면 전환 단계(로딩 대기 등)가 별도 Step으로 분리되어 있는가
- [ ] 사람의 판단이 개입하는 단계가 명시되어 있는가 (자동화 부적합 신호)

## 4. 입력/출력 데이터 명세

### 입력 데이터
- **데이터 출처**: 어디서 받는가 (이메일 첨부, 공유폴더, DB, 시스템 다운로드)
- **데이터 형식**: Excel, CSV, PDF, 화면 캡처, 메일 본문 등
- **데이터 구조**: 컬럼 목록, 데이터 타입, 필수/선택
- **데이터 양**: 건당 행 수, 일/월 누적 건수
- **데이터 품질**: 표준화 정도 (예: 날짜 형식 일관성, 결측치 처리 규칙)

### 출력 데이터
- **저장 위치**: 어느 시스템/폴더/DB
- **저장 형식**: 파일 형식, DB 테이블명
- **후속 처리**: 누가 이어서 사용하는가, 알림이 필요한가

### 도출 팁
- 비정형 입력(자유 텍스트, 이미지)은 자동화 부적합 신호
- 입력 데이터의 양식이 매번 다르면 RPA보다 IDP(Intelligent Document Processing) 결합 필요
- 출력 후 누가 검수하는지 명시 (완전 무인 자동화 vs 사람 검수 단계)

### 체크리스트
- [ ] 입력 데이터의 형식이 표준화되어 있는가
- [ ] 입력 데이터의 검증 규칙이 명시되어 있는가
- [ ] 출력 데이터의 저장 위치와 명명 규칙이 명시되어 있는가

## 5. 예외 처리/분기 조건

### 도출해야 할 정보
정상 케이스(Happy Path) 외 모든 분기:

**비즈니스 분기**
- 데이터 값에 따른 처리 분기 (예: 금액 1억 이상은 결재 요청)
- 거래처 유형별 처리 차이
- 우선순위에 따른 처리 순서 변경

**시스템 예외**
- 시스템 응답 지연/타임아웃
- 로그인 실패
- 데이터 조회 결과 없음
- 중복 데이터
- 권한 부족

**데이터 예외**
- 입력 데이터 누락 필드
- 형식 오류 (날짜, 숫자)
- 마스터 데이터 미등록 (예: 신규 거래처)

### 작성 형식
| 예외 유형 | 발생 조건 | 처리 방법 | 알림 대상 |
|-----------|-----------|-----------|-----------|
| 거래처 미등록 | 거래처코드 조회 결과 없음 | 처리 보류, 담당자 메일 발송 | 김ㅇㅇ 대리 |
| 시스템 타임아웃 | 30초 무응답 | 3회 재시도 후 실패 처리 | 운영팀 |

### 도출 팁
- 현업 자료에 예외 처리가 없으면 99% "확인 필요" 사항으로 표기
- 현업 인터뷰 시 "한 번이라도 발생했던 이상 케이스"를 모두 수집
- 자동화 후 예외 발생 시 봇이 멈출지, 다음 건으로 넘어갈지 정책 결정 필요

### 체크리스트
- [ ] 모든 시스템 예외에 대한 처리 방법이 정의되어 있는가
- [ ] 예외 발생 시 알림 대상과 방법이 명시되어 있는가
- [ ] 예외 처리 결과를 어떻게 기록/추적할지 정의되어 있는가

## 6. 자동화 가능성 평가

### 평가 기준 (5개 항목, 각 5점)
| 평가 항목 | 5점 | 3점 | 1점 |
|-----------|-----|-----|-----|
| 업무 표준화 | 절차가 명확히 정형화됨 | 일부 변동 있음 | 매번 다름 |
| 데이터 정형성 | 정형 데이터 100% | 일부 비정형 | 비정형 위주 |
| 시스템 안정성 | 안정적, 변경 적음 | 가끔 변경 | 자주 변경 |
| 처리 빈도/볼륨 | 고빈도/고볼륨 | 중간 | 저빈도/소량 |
| 판단 개입 | 거의 없음 | 일부 룰 기반 판단 | 사람 판단 필수 |

### 종합 등급
- **상 (20-25점)**: 완전 자동화 권장, ROI 우수
- **중 (12-19점)**: 부분 자동화 또는 RDA(사람 보조형) 검토
- **하 (5-11점)**: 자동화 부적합, 프로세스 개선 우선

### 자동화 범위 제안
- **완전 자동화(STP)**: 시작부터 종료까지 무인 처리
- **부분 자동화**: 데이터 수집/입력만 자동, 검수는 사람
- **RDA**: 사람이 트리거하면 봇이 일부 작업 수행
- **자동화 보류**: 프로세스 표준화 선행 필요

### 체크리스트
- [ ] 5개 항목별 점수와 근거가 명시되어 있는가
- [ ] 종합 등급에 따른 권고안이 구체적인가
- [ ] 부분 자동화 시 자동화 구간과 수동 구간이 명확한가

## 7. 리스크/제약사항

### 도출해야 할 정보

**기술적 리스크**
- 시스템 변경 가능성 (UI 개편 예정, 차세대 시스템 도입)
- 가상화 환경 사용 여부
- 시스템 응답 속도 불안정

**보안/규제 리스크**
- 개인정보 처리 (PII 포함 여부)
- 금융감독 규제 (전자금융감독규정 등)
- 내부 감사 요건 (로그 보관, 처리 추적)
- 망분리 환경 여부

**운영 리스크**
- 처리 실패 시 비즈니스 영향도
- 봇 운영 시간 (업무시간 외 처리 가능 여부)
- 라이선스 비용 (시스템 동시 접속 라이선스)

**조직적 리스크**
- 현업 부서의 변화 수용도
- 자동화 후 인력 재배치 계획

### 도출 팁
- 현업 자료에 리스크 항목은 거의 없음 → 화면 캡처 분석으로 추론
- 개인정보(주민번호, 계좌번호 등)가 포함되면 반드시 보안 검토 항목 추가
- 시스템이 "차세대 도입 예정"인 경우 자동화 우선순위 재검토 권고

### 체크리스트
- [ ] 보안/규제 리스크가 검토되었는가
- [ ] 시스템 변경 일정이 확인되었는가
- [ ] 처리 실패 시 영향도와 복구 방안이 명시되어 있는가
